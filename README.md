# RealityGlitch 2.0

2026-10-31 新建的独立原型，Git 历史不包含旧项目提交。项目应用代码为本次开发重新编写；姿态识别所用 MediaPipe、React、Three.js 等是第三方依赖，模型和 WASM 也是第三方文件，并非本项目原创代码。赛事对第三方依赖、模型及代码生成的具体规则应以主办方规定为准。

## 当前试玩：三线宝石挑战（2026-10-31）

正式入口现为三线宝石挑战：玩家在画面内左右移动，系统按髋部实时位置选择路线，怪物由远及近，挥拳击败已进入攻击范围的当前路线怪物，掉落同色宝石；右侧同色三颗自动消除。测试规则为 3 格生命、90 秒、5 次三消，8 个宝石格满或生命/时间耗尽失败。路线调整面板支持上下、左右、间距及视觉景深；镜像和画面留边均计入位置映射，尚需真人 iPhone 验证。丢失人体时保留上一次路线。先前单 Boss 模式保留在 `?boss-classic`，动作测试仍为 `?pose-test`。

目前五色怪物共用一个导入的 GLB 或程序化占位物，宝石为占位图形；刷新后需重新导入，尚未接入五个正式怪物资产或正式宝石资产。熔岩巨人约 193 万面，多只同时显示可能卡顿，请使用优化模型并做现场测试。游戏键盘回退：左/右方向键切换，空格攻击。命中、挥空、三消和受伤具有画面及程序合成音效，浏览器需点击开始以启用音频。red骨骼.glb 含 Mixamo 骨骼和蒙皮但无动画片段，游戏提供程序化骨骼跑步；red1.glb 没有骨骼/动画，但独立部件可在游戏中程序化摆动。实际动作质量需用户现场确认。

## 原单 Boss 原型（保留作对照）

- 手机通过本机信令和 WebRTC 传递画面，视频在设备间传输。
- 实时视频是背景，3D Boss 覆盖在画面上；不进行人体分割或场景深度重建。
- 本地 Pose 模型识别挥拳、侧身、下蹲、双手举高；动作测试页经真人初测并调整，完整战斗中仍需真人复测。
- 两套手选本地预设；物品扫描可将模型结果匹配到本地场景。Boss 和场景是程序化占位，不是最终美术。
- 战斗逻辑本地运行；可用空格、方向键、F 做调试回退。
- Boss 会交替预警冲击波和横扫：前者侧身闪避，后者下蹲闪避；两个预警和动作配合仍需真人测试。
- 终结技需要能量满且 Boss 血量不高于 35%；双手举高触发封印动画，随后进入结算。结算展示挥拳命中、成功闪避、受击次数和战斗时间。

## 启动

需要 Node.js 20+、Python 3.11+、Chrome 或 Edge。

```powershell
cd server
python -m pip install -r requirements.txt
python -m uvicorn main:app --host 127.0.0.1 --port 8012
```

另开终端：

```powershell
cd app
npm ci
npm run dev
```

电脑访问 https://localhost:5174 。手机连同一 Wi-Fi 或电脑热点，点击手机直连，选择手机可以访问的网络地址，扫码并允许手机摄像头；本地 HTTPS 使用自签名证书，手机需要由使用者自行接受浏览器提示。手机横放、固定并拍到肩、双手和髋，站直点击重新校准。

运行 `cd app; npm test; npm run build`，以及 `python -m unittest discover -s server`。现场网络、识别准确率和性能仍以实测为准。

## 物品扫描

电脑端主动点击扫描时，当前画面的一帧会发送到配置的视觉模型服务。`server/.env` 支持 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 与 `LLM_VISION=true`，不会提交密钥。模型结果通过字段与枚举校验后匹配到两套本地场景；联网模型尚未实测。失败时保留本地预设。

## 本地 Boss 资产

“放置怪物”中的“选择 Tripo GLB”可从本机选择单文件 GLB；模型和贴图在浏览器本地加载，不上传。外部引用的资源会被拒绝，文件需包含贴图，且不超过 100 MB。可在“放置怪物”中调整位置、大小和朝向。读取失败时使用占位 Boss；所选文件不会在刷新后保存。支持静态加载与程序化受击运动，当前不自动播放模型自带动画。实际 Tripo 文件、授权与现场性能需要另行验收。



## 实景估计功能（实验）

固定手机并让一个人的全身、双脚稳定入镜。程序以脚部关键点高度估计落点，并将怪物放在画面另一侧；这不是平面检测或实际深度测量。点击“放置怪物”可修正位置并锁定背景纹理。跟踪只估计小幅二维平移，遇到旋转、强遮挡或大幅运动可能丢失，丢失后位置冻结并提示重新锁定。


正式战斗页直接使用摄像头实景作为背景，叠加本地 3D 怪物，不运行深度场景重建或人体分割。深度对比页仅保留为独立历史实验。姿态识别优先在后台线程运行，兼容模式自动回退。
